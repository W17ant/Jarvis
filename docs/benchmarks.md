# Benchmarks

> _This file is regenerated by `npm run benchmark` against a running bridge. It currently contains placeholder copy because no voice turns have been recorded since the last reset._

## How to populate

```bash
./launch.sh restart           # clean perf buffer
# Wake Jarvis and run 20+ natural voice turns:
#   "hey jarvis, what's the weather"
#   "hey jarvis, what time is it"
#   "hey jarvis, list my emails"
#   ...
npm run benchmark             # scrape /health/timings + /health/sessions, regenerate this file
```

Add `--transcribe-smoke` for an additional pure-STT block (requires `test/fixtures/hello-jarvis.wav`):

```bash
npm run benchmark -- --transcribe-smoke
```

## What gets measured

`tools/benchmark.mjs` scrapes two bridge endpoints:

| Endpoint | What it returns |
|---|---|
| `GET /health/timings` | p50/p95 across 5 spans of the last 50 voice turns (in-memory rolling buffer) |
| `GET /health/sessions?days=14` | Per-day persisted aggregates from `data/audit/sessions/YYYY-MM-DD.jsonl` |

The headline number is `voice_to_audio` p50 — the time from wake-word firing to the first audio sample hitting your output device. Target: **<1.0s p50** on Apple Silicon. The sentence segmenter was loosened to comma/colon at ≥12 chars for the first chunk specifically to hit this.

## Methodology

1. `voice.js` fires `performance.mark()` at four boundaries: wake-start, rec-end, whisper-req, whisper-res.
2. `tts-pipeline.js` fires `v.audio-play` at `source.start(0)` — the moment the first audio sample plays.
3. `voice.js _reportPerfTimings()` POSTs the span summary to `/perf` after each turn.
4. The bridge appends to a rolling 50-entry buffer AND writes to the per-day session log.
5. This script reads both, computes p50/p95, and renders this file.

## Hardware variance

Numbers will differ between an M1 Max with 64GB and an M3 Pro with 18GB. There's no single "Jarvis is fast" claim — re-run the benchmark on each operator's machine.

## Reproducibility

The output is committed at `docs/benchmarks.md` and overwritten on every run. To preserve a snapshot for comparison, copy to a dated archive before re-running:

```bash
cp docs/benchmarks.md docs/benchmarks/2026-05-09.md
npm run benchmark             # overwrites docs/benchmarks.md with fresh numbers
```
